================================================================================
СЦЕНАРИЙ ДЛЯ ЗАЩИТЫ: заказ на сайте → данные для информационной базы 1С
================================================================================

ИДЕЯ ДЛЯ КОМИССИИ
  Интернет-магазин сохраняет заказ в своей БД (PostgreSQL) и одновременно
  выгружает структурированное описание заказа в формате JSON в каталог,
  из которого конфигурация 1С может создавать документы (обработка,
  регламентное задание или ручной запуск). Это стандартный приём интеграции
  без обязательной публикации 1С на IIS.

--------------------------------------------------------------------------------
ЧТО НАСТРОИТЬ ПЕРЕД ПОКАЗОМ
--------------------------------------------------------------------------------

1) PostgreSQL и бэкенд запущены (как обычно).

2) Файл .env должен лежать в каталоге auto-parts-shop/backend/ (рядом с папкой app).
   Скопируйте .env.example в .env и укажите каталог выгрузки, например:

     ONEC_ORDER_EXPORT_DIR=C:/Users/User/Documents/ShopOrdersFor1C

   (папку можно создать заранее; права на запись у процесса uvicorn.)
   Если .env лежал в другом месте — переменная не подхватывалась; это исправлено в коде.

3) Перезапустите uvicorn.

4) Откройте сайт, оформите заказ до конца (корзина → оформление).

--------------------------------------------------------------------------------
ЧТО ПОКАЗАТЬ НА ЗАЩИТЕ (пошагово)
--------------------------------------------------------------------------------

А) Сайт: оформить заказ — комиссия видит успешное завершение на UI.

Б) Папка ONEC_ORDER_EXPORT_DIR: появился файл order_<номер>.json с полями
   id_заказа, клиент (ФИО, email, телефон, адрес), позиции (артикул, название,
   количество, цены), общая_сумма — это «пакет данных для 1С».

В) Инструменты разработчика браузера (вкладка Сеть) → запрос POST .../api/orders/:
   в ответе смотрите заголовки:
     X-OneC-Export-Status: ok
     X-OneC-Export-Path: полный путь к записанному JSON
   Так видно, что бэкенд явно передал заказ в канал интеграции с 1С.

Г) 1С: открыть вашу ИБ (например InfoBase19). На защите достаточно одного из:
     • запустить внешнюю обработку, которая читает JSON из этой папки и
       создаёт документ (шаблон логики — ImportOrderFromJsonFile.bsl.txt);
     • или показать в конфигураторе/отладчике чтение того же файла и
       заполнение реквизитов документа (даже без полного проведения);
     • или кратко объяснить регламентное задание «каждые N минут импорт
       из каталога» — для диплома часто принимают вместе с рабочим JSON.

--------------------------------------------------------------------------------
ФОРМУЛИРОВКА (можно почти дословно)
--------------------------------------------------------------------------------

  «После подтверждения заказа веб-приложение фиксирует его в SQL-базе магазина
  и формирует JSON-файл в обменном каталоге в формате, согласованном для
  загрузки в 1С. Дальнейшее создание документа в информационной базе выполняет
  прикладной код 1С по этому файлу; при необходимости тот же контракт может
  быть реализован через HTTP-сервис 1С.»

--------------------------------------------------------------------------------
ЕСЛИ СПРОСЯТ ПРО «ПРЯМО В БАЗУ БЕЗ ФАЙЛА»
--------------------------------------------------------------------------------

  Ответ: для файловой ИБ без публикации веб-сервера надёжный путь — обмен
  через каталог или COM на одной машине; HTTP-сервис 1С требует IIS/Apache
  и модуль платформы. В работе реализован канал файловой выгрузки и опционально
  вебхук (ONEC_ORDER_WEBHOOK_URL), когда инфраструктура будет доступна.

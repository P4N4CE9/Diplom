================================================================================
КАК JSON С САЙТА ПОПАДАЕТ В СИСТЕМУ 1С
================================================================================

Файл order_<id>.json сам по себе в базу 1С не «въезжает». Его нужно ОБРАБОТАТЬ
программой на встроенном языке 1С: прочитать JSON, создать документ (или другой
объект), записать в ИБ, затем файл обычно удаляют или переносят в «архив».

Ниже три рабочих схемы — для диплома чаще всего хватает варианта 1.

--------------------------------------------------------------------------------
1) ВНЕШНЯЯ ОБРАБОТКА (удобно для защиты и отладки)
--------------------------------------------------------------------------------

  • В конфигураторе: Файл → Новый → Внешняя обработка (или обработка в расширении).
  • На форму выведите поле «Путь к папке» (как ONEC_ORDER_EXPORT_DIR) и кнопку
    «Загрузить заказы».
  • В модуле формы по нажатию вызывайте процедуру из шаблона
    ImportOrderFromJsonFile.bsl.txt (логика чтения файлов и JSON там уже есть).
  • Вместо блока TODO подставьте создание ВАШЕГО документа и заполнение ТЧ.

  Плюсы: не нужен веб-сервер, на защите открываете 1С, нажимаете кнопку —
  документы появляются в списке.

--------------------------------------------------------------------------------
2) РЕГЛАМЕНТНОЕ ЗАДАНИЕ (как «фоновая интеграция») — ГОТОВЫЙ ШАБЛОН В РЕПОЗИТОРИИ
--------------------------------------------------------------------------------

  • Код общего модуля:  onec/CommonModule_РеглЗагрузкаЗаказовССайта.bsl.txt
  • Пошаговая настройка: onec/REG_SCHEDULED_JOB_SETUP.txt
  • Константа в 1С: ПутьВходящихЗаказовИнтернетМагазина (= путь как на сайте).
  • После успешного разбора JSON файл переносится в подпапку «обработано»;
    в журнал пишется событие «ИнтернетМагазин.ЗагрузкаЗаказов».

  Плюсы: похоже на промышленный обмен; для файловой ИБ см. предупреждение
  в REG_SCHEDULED_JOB_SETUP.txt про фоновый запуск.

--------------------------------------------------------------------------------
3) HTTP-СЕРВИС 1С (без файла, если настроите публикацию)
--------------------------------------------------------------------------------

  Сайт шлёт POST с тем же JSON (ONEC_ORDER_WEBHOOK_URL). Код приёма — в файле
  ShopOrderWebhook.bsl.txt. Это другой канал, смысл тот же: создать документ в ИБ.

================================================================================
ЧТО ИМЕННО ПИСАТЬ ВМЕСТО TODO (суть для пояснительной записки)
================================================================================

  1. Разобрать структуру Данные после ПрочитатьJSON (поля как в JSON с сайта):
     id_заказа, дата_заказа, статус, способ_оплаты, общая_сумма,
     клиент (id_клиента, фио, email, телефон, адрес),
     позиции[] (id_запчасти, артикул, название, количество, цена, сумма).

  2. Создать документ вашей конфигурации, например:
     Документы.ЗаказПокупателя.СоздатьДокумент()  — имя ЗАВИСИТ от конфигурации.

  3. Заполнить шапку: контрагент (поиск в справочнике по email/телефону или
     создание нового элемента), комментарий с id_заказа с сайта.

  4. Заполнить табличную часть: для каждой строки позиции найти номенклатуру
     по артикулу (или создать), указать количество и цену.

  5. Документ.Записать(РежимЗаписиДокумента.Запись) или Проведение — по правилам УЧЁТА.

  Имена справочников, документов и реквизитов смотрите в КОНФИГУРАТОРЕ своей ИБ
  (дерево конфигурации). У учебной и типовой УТ/УНФ они разные — универсального
  кода без вашей базы не существует.

================================================================================
СТРУКТУРА JSON (для справки)
================================================================================

  Откройте любой order_*.json блокнотом — это и есть контракт обмена между
  сайтом и вашим модулем 1С.
